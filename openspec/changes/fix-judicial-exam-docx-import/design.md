## Context

现有 `_parse_word_questions` 函数支持三种格式：
1. **标记格式**：以【题型】开头，如【单选题】
2. **编号格式**：以数字序号开头，如 `1. 题目内容`
3. **无标记格式**：题目内容以括号结尾

用户导入的司法鉴定题库文件可能采用不同的格式，如：
- 表格形式组织的题目（每行一个题目，选项在不同列）
- 特殊编号格式（一、题目内容 或 【1】题目内容）
- 题目与选项在同一段落混排

## Goals / Non-Goals

**Goals:**
- 增强 Word 题目解析器，支持表格格式
- 支持更多编号格式变体（中文数字序号、括号编号）
- 改进选项解析逻辑，处理选项与题目混排的情况
- 添加调试日志，方便排查解析问题

**Non-Goals:**
- 不支持图片题目（需要单独处理）
- 不改变现有 API 接口
- 不修改 Excel 导入逻辑

## Decisions

### Decision 1: 表格解析增强

**选择**：在现有解析流程中增加表格解析分支

**理由**：
- `python-docx` 支持提取表格数据，实现简单
- 表格格式是正式考试文件常用格式
- 可以在不破坏现有解析逻辑的情况下增量添加

**实现方式**：
```python
# 在 _parse_word_questions 中新增
def _parse_word_from_tables(doc):
    """从表格中解析题目"""
    # 遍历所有表格，尝试识别题目格式
    pass
```

### Decision 2: 编号格式兼容性

**选择**：扩展正则表达式匹配更多编号变体

**理由**：
- 现有正则 `r'^(\d+)[．、.。]?\s*(.+)$'` 较为严格
- 司法鉴定文件可能使用【1】、一、等不同序号
- 正则扩展成本低，覆盖广

**新增匹配模式**：
- `r'^【(\d+)】\s*(.+)$'` - 【1】格式
- `r'^([一二三四五六七八九十]+)[．、.。]\s*(.+)$'` - 中文数字格式

### Decision 3: 选项解析优化

**选择**：识别选项与题目在同一段落的情况

**理由**：
- 部分文件选项与题目用空格分隔而非换行
- 如 `题目内容 A. 选项1 B. 选项2 C. 选项3 D. 选项4`

**实现**：
- 增加选项识别模式，支持 `A. xxx B. xxx` 单行格式

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 新格式可能引入新的解析边界情况 | 添加解析失败时的错误日志，记录未解析的行 |
| 表格解析可能误识别非题目表格 | 增加格式校验，表格需包含题型/选项等关键字 |
| 正则扩展可能降低性能 | 仅在常规解析失败后尝试，避免性能影响 |
