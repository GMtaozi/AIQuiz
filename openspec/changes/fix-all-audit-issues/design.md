## Context

系统上线前终审发现了多个需要修复的问题，涵盖安全、稳定性、合规三个维度。系统当前使用FastAPI+Vue 3架构，AI出题依赖MiniMax API。

## Goals / Non-Goals

**Goals:**
- 修复所有P0（致命）和P1（严重）问题，确保系统可安全上线
- 修复P2/P3体验问题，提升系统稳定性
- 补充法律合规文案，满足商用要求

**Non-Goals:**
- 不重构核心业务逻辑
- 不改变现有API接口契约（仅修复合规问题）
- 不迁移数据库结构

## Decisions

### 1. 异步任务执行架构

**决策**: 使用 `concurrent.futures.ThreadPoolExecutor` 替代直接操作 `asyncio.new_event_loop()`

**理由**:
- 避免在子线程创建事件循环的潜在问题
- ThreadPoolExecutor 是标准库，稳定性好
- 与FastAPI的异步框架兼容

**替代方案考虑**:
- 使用 `asyncio.run()` - 但不适合在已运行的事件循环中嵌套
- 直接使用同步代码 - 放弃异步优势，不可行

### 2. AI配置加载优先级

**决策**: 明确优先级顺序：环境变量(.env) > 数据库配置(SystemSetting) > 代码默认值

**理由**:
- 环境变量适合敏感信息（生产环境）
- 数据库配置适合运行时动态调整
- 代码默认值保证最小可用性

### 3. 前端权限拦截

**决策**: 在API拦截器层统一处理权限检查，而非在每个组件内单独处理

**理由**:
- 集中管理，减少遗漏
- 与后端权限体系对齐
- 便于后续扩展权限类型

### 4. SQL注入防护

**决策**: 使用 `ilike()` 配合转义，而非依赖ORM自动防护

**理由**:
- `contains()` 实际使用LIKE后缀通配符，有注入风险
- `ilike()` 提供大小写不敏感搜索
- 转义特殊字符 `%` 和 `_` 是标准做法

### 5. 合规文案方案

**决策**: 登录/注册页面底部添加法律文本链接弹窗显示

**理由**:
- 不影响主流程交互
- 法律文本可完整展示
- 符合行业通行做法

## Risks / Trade-offs

| 风险 | 描述 | 缓解措施 |
|------|------|----------|
| R1 | 异步任务重构可能引入新问题 | 在测试环境充分验证高并发场景 |
| R2 | 修改字体路径可能影响Windows用户 | 保留原有路径作为首选 |
| R3 | 法律文本需要法务审核 | 预留文本模板，可快速替换 |

## Migration Plan

1. **Phase 1 (P0修复)**: 修复线程安全、Group ID、越权问题
2. **Phase 2 (P1修复)**: 修复配置、注入、分数问题
3. **Phase 3 (P2/P3+合规)**: 体验优化和法律文案
4. **Phase 4**: 回归测试，验证所有修复无副作用

**回滚策略**: 所有修改通过git管理，可快速回退到上一版本
